# GitHub App for repository automation

Use one repository-scoped GitHub App, for example `microtik-containers-bot`.

## Required repository permissions

- **Contents:** Read and write
- **Pull requests:** Read and write
- **Issues:** Read and write
- **Metadata:** Read (implicit)

Do not grant Administration, Actions, Secrets or a ruleset bypass. Install the App only on `dedalodaelus/microtik-containers`.

Store its credentials as:

```text
Variable: BOT_APP_CLIENT_ID
Secret:   BOT_APP_PRIVATE_KEY
```

The private key is the PEM generated by GitHub. Workflows use `actions/create-github-app-token@v3` to create short-lived installation tokens.

The App is used by the Buildroot updater, Release Please, Release Please PR re-signing and the explicit **Merge bot PR** workflow. It is intentionally not a bypass actor for the `main` ruleset.

## Why API-created commits are used

GitHub's bot signature model works when a request is authenticated as a GitHub App/bot and does not supply custom author, committer or signature information. The repository helpers follow that model and check GitHub's returned verification result before publishing a branch.

Release Please computes release contents normally. If its release PR head is not Verified, `scripts/resign-release-pr.py` rewrites that release branch with the same files in a Verified App-authored commit.
